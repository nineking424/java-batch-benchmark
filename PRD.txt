# PRD: Oracle JDBC Batch vs MyBatis Batch 성능 비교 벤치마크

## 1. 개요

Oracle 데이터베이스 환경에서 순수 JDBC Batch 방식과 MyBatis ExecutorType.BATCH 방식의 INSERT 성능을 비교하는 벤치마크 프로젝트를 Java로 작성한다.

## 2. 프로젝트 구성

### 2.1 빌드 환경
- 빌드 도구: Maven
- Java 버전: 17
- 기본 패키지: com.example.benchmark

### 2.2 의존성
- Oracle JDBC Driver: ojdbc11 (23.x)
- MyBatis: 3.5.x
- HikariCP: 5.x (커넥션 풀)
- Logback: 1.4.x (로깅)

## 3. 테스트 대상

### 3.1 JDBC Batch
- PreparedStatement.addBatch() + executeBatch() 직접 사용
- Connection.setAutoCommit(false) 설정
- 배치 사이즈마다 executeBatch() 호출 후 clearBatch()

### 3.2 MyBatis ExecutorType.BATCH
- SqlSessionFactory.openSession(ExecutorType.BATCH, false)로 세션 생성
- 배치 사이즈마다 session.flushStatements() 호출
- session.clearCache()로 메모리 관리

### 3.3 MyBatis 단건 INSERT (비교 기준)
- ExecutorType.SIMPLE 사용
- 각 INSERT마다 개별 실행
- 레코드 수 10,000건 이하일 때만 실행 (시간 소요로 인해)

## 4. 도메인 모델

### 4.1 Item 클래스
```
필드:
- id: Long (PK, 시퀀스로 생성)
- name: String (VARCHAR2(100), NOT NULL)
- description: String (VARCHAR2(500))
- quantity: int (NUMBER(10), DEFAULT 0)
- price: double (NUMBER(15,2), DEFAULT 0)
```

### 4.2 데이터베이스 객체
- 테이블명: benchmark_items
- 시퀀스명: benchmark_items_seq
- 인덱스: idx_benchmark_items_name (name 컬럼)

## 5. 설정 파일

### 5.1 application.properties
```
# 데이터베이스 연결
db.url=jdbc:oracle:thin:@//localhost:1521/XEPDB1
db.username=benchmark_user
db.password=benchmark_password

# HikariCP 설정
hikari.maximumPoolSize=10
hikari.minimumIdle=5
hikari.connectionTimeout=30000

# 벤치마크 설정
benchmark.recordCount=10000
benchmark.batchSize=1000
benchmark.warmupIterations=2
benchmark.testIterations=5
```

### 5.2 mybatis-config.xml
- cacheEnabled: false
- lazyLoadingEnabled: false
- useGeneratedKeys: false
- defaultExecutorType: SIMPLE

### 5.3 logback.xml
- SQL 로깅 비활성화 (벤치마크 정확도를 위해)
- org.apache.ibatis: WARN
- java.sql: WARN
- com.zaxxer.hikari: WARN

## 6. 벤치마크 실행 흐름

### 6.1 초기화 단계
1. 기존 테이블/시퀀스 DROP (존재하면)
2. 테이블 생성 (benchmark_items)
3. 시퀀스 생성 (benchmark_items_seq)
4. 인덱스 생성

### 6.2 데이터 준비
1. 설정된 레코드 수만큼 Item 객체 생성
2. name: "Item-" + 8자리 숫자 (예: Item-00000001)
3. description: 고정 문자열 + 인덱스
4. quantity: 0~999 랜덤
5. price: 0~10000 랜덤 (소수점 2자리)

### 6.3 테스트 실행
각 테스트 방식별로:
1. Warmup 실행 (설정된 횟수만큼)
   - 테이블 truncate
   - INSERT 실행
2. 실제 테스트 실행 (설정된 횟수만큼)
   - 테이블 truncate
   - 시작 시간 기록
   - INSERT 실행
   - 종료 시간 기록
   - 레코드 수 검증
   - 실행 시간 저장

### 6.4 배치 처리 로직
- 매 batchSize 건마다:
  - JDBC: executeBatch() + clearBatch()
  - MyBatis: flushStatements() + clearCache()
- 마지막 남은 건 처리

## 7. 결과 통계

### 7.1 BenchmarkResult 클래스
각 테스트 방식별로 다음 통계 계산:
- 평균 실행 시간 (ms)
- 중앙값 실행 시간 (ms)
- 최소 실행 시간 (ms)
- 최대 실행 시간 (ms)
- 표준편차 (ms)
- 처리량 (records/sec)

### 7.2 비교 분석
- JDBC vs MyBatis 실행 시간 차이 (ms)
- 성능 차이 비율 (%)
- 승자 표시
- Batch vs Single 성능 향상 배율

## 10. 실행 방법

### 10.1 데이터베이스 준비
```sql
CREATE USER benchmark_user IDENTIFIED BY benchmark_password;
GRANT CONNECT, RESOURCE TO benchmark_user;
GRANT CREATE TABLE, CREATE SEQUENCE TO benchmark_user;
ALTER USER benchmark_user QUOTA UNLIMITED ON USERS;
```

### 10.2 설정 수정
application.properties에서 DB 접속 정보 수정

### 10.3 실행
```bash
mvn clean compile
mvn exec:java -Dexec.mainClass="com.example.benchmark.BatchBenchmark"
```
